# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## Система управления задачами и мероприятиями

---

## 1. ОБЩЕЕ ОПИСАНИЕ ПРОЕКТА

### 1.1. Назначение системы
Разработка веб-приложения для управления задачами и мероприятиями организации с поддержкой многоуровневого согласования, контроля выполнения, замещения сотрудников и аналитики.

### 1.2. Целевая аудитория
- Директор организации
- Заместители директора
- Руководители отделов
- Сотрудники с повышенными правами
- Обычные сотрудники

### 1.3. Основные цели
- Централизованное управление задачами и мероприятиями
- Автоматизация процессов согласования и проверки
- Контроль сроков выполнения задач
- Аналитика и отчетность по выполнению задач
- Оптимизация рабочих процессов организации

---

## 2. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

### 2.1. Аутентификация и авторизация

#### 2.1.1. Вход в систему
- **Вход по логину и паролю** через веб-интерфейс
- **Сессионная аутентификация** (Django Sessions)
- **CSRF защита** всех форм
- **Автоматическая проверка** аутентификации при загрузке приложения
- **Защищенные маршруты** - доступ только для авторизованных пользователей
- **Автоматический редирект** на страницу входа для неавторизованных пользователей

#### 2.1.2. Управление профилем
- **Просмотр профиля** текущего пользователя
- **Редактирование профиля** (ФИО, должность, контакты)
- **Загрузка фото профиля**
- **Смена пароля**
- **Просмотр информации о роли и отделе**

#### 2.1.3. Роли и права доступа
Система должна поддерживать следующие роли:

**Директор (director)**
- Полный доступ ко всем функциям системы
- Утверждение планов мероприятий
- Просмотр всех задач и мероприятий
- Управление сотрудниками и отделами

**Заместитель директора (deputy)**
- Утверждение планов мероприятий
- Согласование создания задач (если не согласно плана)
- Просмотр всех задач и мероприятий
- Создание задач в любых мероприятиях

**Руководитель отдела (head)**
- Управление задачами своего отдела
- Согласование создания задач сотрудников отдела
- Создание задач в мероприятиях своего отдела
- Просмотр задач своего отдела

**Сотрудник с повышенными правами (senior)**
- Создание задач в мероприятиях своего отдела
- Просмотр задач своего отдела
- Выполнение назначенных задач

**Обычный сотрудник (staff)**
- Просмотр назначенных задач
- Выполнение назначенных задач
- Создание задач с обязательным согласованием (если не согласно плана)

### 2.2. Управление мероприятиями (EventCard)

#### 2.2.1. Создание мероприятия
- **Название мероприятия** (обязательное поле)
- **Описание мероприятия** (текстовое поле)
- **Дата начала** (обязательное поле)
- **Дата окончания** (опциональное поле)
- **Ответственный отдел** (выбор из списка отделов)
- **Совместные отделы** (множественный выбор отделов, которые также могут создавать задачи)
- **Категории мероприятия** (множественный выбор из существующих категорий)
- **Флаг "С планом мероприятия"** - определяет, требуется ли загрузка и утверждение плана
- **Назначение согласующих** (цепочка согласующих в определенном порядке)
- **Финальный утверждающий** (директор или заместитель)

#### 2.2.2. План мероприятия
Если мероприятие создано с флагом "С планом мероприятия":
- **Загрузка файла плана** (PDF, DOC, DOCX, XLS, XLSX)
- **Статусы плана:**
  - Черновик (draft) - план загружен, но не отправлен на согласование
  - На согласовании (pending) - план отправлен на согласование
  - Отклонён (rejected) - план отклонен одним из согласующих
  - Утверждён (approved) - план утвержден всеми согласующими
- **Цепочка согласования плана:**
  - Последовательное согласование назначенными согласующими
  - После согласования всеми - передача финальному утверждающему
  - После утверждения - мероприятие становится видимым для создания задач
- **Причина отклонения** (обязательна при отклонении)
- **Загрузка исправленного плана** после отклонения
- **История согласования** (кто и когда согласовал/отклонил)

#### 2.2.3. Просмотр мероприятий
- **Список всех мероприятий** с фильтрацией:
  - По категориям
  - По статусу плана (для мероприятий с планом)
  - По дате начала/окончания
  - По ответственному отделу
- **Детальная страница мероприятия:**
  - Полная информация о мероприятии
  - Список всех задач мероприятия
  - Прогресс выполнения (процент выполненных задач)
  - Статистика по задачам:
    - Общее количество задач
    - Количество выполненных задач
    - Количество активных задач пользователя
    - Количество срочных задач пользователя
    - Количество задач на согласовании пользователя
    - Прогресс пользователя
    - Прогресс отдела
  - История изменений

#### 2.2.4. Редактирование мероприятия
- Редактирование всех полей (кроме создателя)
- Изменение цепочки согласующих (до начала согласования)
- Изменение финального утверждающего (до утверждения)

#### 2.2.5. Удаление мероприятия
- Удаление возможно только если нет связанных задач
- Мягкое удаление (архивирование) рекомендуется

### 2.3. Управление задачами (Task)

#### 2.3.1. Типы задач
Система должна поддерживать следующие типы задач:

**Обычная задача (regular)**
- Стандартная задача на выполнение

**Согласование плана (approval)**
- Задача для согласования плана мероприятия
- Создается автоматически при отправке плана на согласование

**Согласование выполнения (review)**
- Задача для проверки выполненной работы
- Создается автоматически при отправке задачи на проверку

**Согласование задачи (task_approval)**
- Задача для согласования создания другой задачи
- Создается автоматически при создании задачи не согласно плана

#### 2.3.2. Статусы задач
- **Новая (new)** - задача создана, но еще не взята в работу
- **В работе (in_progress)** - задача взята в работу исполнителем
- **Отправлено на проверку (sent_for_review)** - задача выполнена и отправлена на проверку
- **На проверке (under_review)** - задача находится на проверке у проверяющего
- **Выполнена (done)** - задача выполнена и проверена
- **Отклонена (rejected)** - задача отклонена проверяющим или согласующим
- **На согласовании (pending)** - задача находится на согласовании создания
- **На пересмотрении (revision)** - задача отправлена на доработку после проверки
- **Отправлено на согласование (send_for_approve)** - задача отправлена на согласование создания

#### 2.3.3. Приоритеты задач
- **Обычная (normal)** - стандартный приоритет
- **Срочная (urgent)** - требует немедленного внимания

#### 2.3.4. Создание задачи
**Обязательные поля:**
- Название задачи
- Срок выполнения (дата и время)
- Адресаты (минимум один сотрудник)

**Опциональные поля:**
- Описание задачи
- Приоритет (по умолчанию "Обычная")
- Связь с мероприятием (если задача создается в рамках мероприятия)
- Файл-вложение
- Ссылка на Google Диск
- Флаг "Согласно плана" / "Не согласно плана"

**Логика создания:**
- Если задача создается **согласно плана**:
  - Создается сразу со статусом "Новая"
  - Назначается первому адресату
- Если задача создается **не согласно плана**:
  - Для обычных сотрудников, сотрудников с повышенными правами и руководителей отделов:
    - Требуется выбор заместителя для согласования
    - Создается задача со статусом "На согласовании"
    - Автоматически создается связанная задача типа "Согласование задачи" для выбранного заместителя
  - Для директора и заместителей:
    - Создается сразу со статусом "Новая"

**Проверки при создании:**
- Если задача создается в рамках мероприятия с планом:
  - Проверка, что план мероприятия утвержден
  - Проверка, что мероприятие активно (текущая дата в диапазоне дат мероприятия)
- Если задача создается в рамках мероприятия без плана:
  - Проверка, что мероприятие активно

**Права на создание задач:**
- Директор и заместители могут создавать задачи в любых мероприятиях
- Руководители отделов и сотрудники с повышенными правами могут создавать задачи в мероприятиях своего отдела или совместных отделов
- Обычные сотрудники могут создавать задачи только в мероприятиях своего отдела (с обязательным согласованием, если не согласно плана)

#### 2.3.5. Просмотр задач
- **Список задач** с фильтрацией:
  - По статусу
  - По типу задачи
  - По приоритету
  - По мероприятию
  - По исполнителю
  - По отделу
  - По дате создания/сроку выполнения
  - Поиск по названию и описанию
- **Детальная страница задачи:**
  - Полная информация о задаче
  - История изменений (TaskHistory)
  - Комментарии к задаче
  - Вложения (файлы и ссылки)
  - Информация о цепочке перенаправлений
  - Информация о цепочке проверяющих
  - Информация о цепочке согласования создания (если применимо)
  - Текущий проверяющий (если задача на проверке)
  - Связанные задачи (родительская/дочерние)

#### 2.3.6. Взятие задачи в работу
- Исполнитель может взять задачу в работу (статус меняется на "В работе")
- Запись в истории задачи

#### 2.3.7. Выполнение задачи
- **Страница выполнения задачи:**
  - Поле для описания выполненной работы
  - Загрузка файлов-результатов
  - Добавление ссылок на Google Диск
  - Отправка на проверку
- При отправке на проверку:
  - Статус меняется на "Отправлено на проверку"
  - Если указана цепочка проверяющих:
    - Создается задача типа "Согласование выполнения" для первого проверяющего
    - Статус основной задачи меняется на "На проверке"
  - Если цепочка проверяющих не указана:
    - Задача автоматически завершается (статус "Выполнена")

#### 2.3.8. Проверка выполнения задачи
- **Страница проверки задачи:**
  - Просмотр описания выполненной работы
  - Просмотр прикрепленных файлов и ссылок
  - Поле для комментария проверяющего
  - Кнопки "Утвердить" и "Отклонить"
- **Утверждение:**
  - Если есть следующие проверяющие в цепочке:
    - Создается задача для следующего проверяющего
    - Текущая задача проверки завершается
  - Если это последний проверяющий:
    - Основная задача получает статус "Выполнена"
    - Все задачи проверки завершаются
- **Отклонение:**
  - Основная задача получает статус "На пересмотрении"
  - Задача проверки завершается
  - Исполнитель может доработать и отправить на проверку снова

#### 2.3.9. Согласование создания задачи
- **Страница согласования создания:**
  - Просмотр информации о создаваемой задаче
  - Кнопки "Утвердить" и "Отклонить"
  - Поле для комментария (при отклонении)
- **Утверждение:**
  - Если есть следующие согласующие в цепочке:
    - Создается задача для следующего согласующего
    - Текущая задача согласования завершается
  - Если это последний согласующий:
    - Основная задача получает статус "Новая"
    - Все задачи согласования завершаются
- **Отклонение:**
  - Основная задача получает статус "Отклонена"
  - Все задачи согласования завершаются

#### 2.3.10. Перенаправление задачи
- Возможность перенаправить задачу другому сотруднику или отделу
- Сохранение цепочки перенаправлений
- Уведомление нового исполнителя
- Запись в истории задачи

#### 2.3.11. Редактирование задачи
- Редактирование полей задачи (с учетом прав доступа)
- Изменение срока выполнения
- Изменение приоритета
- Добавление/удаление адресатов
- Добавление/удаление вложений

#### 2.3.12. Комментарии к задачам
- Добавление комментариев к задаче
- Просмотр всех комментариев с указанием автора и времени
- Уведомления участникам задачи о новых комментариях

#### 2.3.13. Вложения к задачам
- Загрузка файлов (любые форматы)
- Добавление ссылок на внешние ресурсы (Google Диск и др.)
- Просмотр списка вложений
- Скачивание файлов
- Удаление вложений (с правами доступа)

#### 2.3.14. Drag-and-Drop для задач
- Возможность перетаскивать задачи между колонками статусов
- Автоматическое изменение статуса при перетаскивании
- Визуальная обратная связь при перетаскивании

### 2.4. Управление сотрудниками и отделами

#### 2.4.1. Сотрудники
- **Список всех сотрудников:**
  - ФИО
  - Должность
  - Отдел
  - Роль
  - Фото профиля
  - Контактная информация (внутренний и внешний телефоны)
- **Детальная страница сотрудника:**
  - Полная информация о сотруднике
  - Список задач сотрудника
  - Статистика выполнения задач
  - Информация о замещении (если активно)

#### 2.4.2. Отделы
- **Список отделов** с приоритетом сортировки
- **Детальная информация об отделе:**
  - Название отдела
  - Список сотрудников отдела
  - Задачи отдела
  - Статистика отдела

#### 2.4.3. Категории мероприятий
- Создание и управление категориями мероприятий
- Привязка категорий к мероприятиям
- Фильтрация мероприятий по категориям

### 2.5. Замещение сотрудников (Delegation)

#### 2.5.1. Настройка замещения
- **Назначение замещающего сотрудника:**
  - Выбор сотрудника, которому передаются полномочия
  - Указание даты окончания замещения
- **Автоматическое применение замещения:**
  - Все задачи, назначенные замещаемому сотруднику, автоматически отображаются у замещающего
  - Замещающий может выполнять все действия от имени замещаемого
  - После окончания срока замещения полномочия возвращаются

#### 2.5.2. Просмотр активных замещений
- Страница "Мои замещения" показывает:
  - Сотрудников, которых замещает текущий пользователь
  - Сотрудников, которые замещают текущего пользователя
  - Даты начала и окончания замещений

#### 2.5.3. Заморозка сотрудника
- При активном замещении сотрудник считается "замороженным"
- Новые задачи не назначаются замороженному сотруднику напрямую
- Все задачи автоматически перенаправляются замещающему

---

### 2.6. Календарь

#### 2.6.1. Отображение задач
- **Календарный вид** с отображением задач по датам дедлайнов
- **Три режима отображения:**
  - Месяц
  - Неделя
  - День
- **Цветовая индикация:**
  - По статусу задачи
  - По приоритету (срочные задачи выделяются)
- **Клик по задаче** - переход на детальную страницу

#### 2.6.2. Фильтрация в календаре
- Фильтрация по статусу
- Фильтрация по типу задачи
- Фильтрация по приоритету
- Фильтрация по мероприятию
- Фильтрация по исполнителю

#### 2.6.3. Локализация
- Русская локализация календаря
- Правильное отображение дат и времени

---

### 2.7. Дашборд (Dashboard)

#### 2.7.1. Статистические карточки
- **Активных карточек** - количество доступных мероприятий
- **Всего задач** - общее количество активных задач
- **Срочные задачи** - количество задач с приоритетом "Срочная" и дедлайном в ближайшие 3 дня
- **На согласовании** - количество задач, ожидающих согласования пользователем

#### 2.7.2. Доска задач
Четыре колонки с задачами:
- **Просроченные задачи** - задачи с истекшим дедлайном
- **Задачи на сегодня** - задачи с дедлайном сегодня
- **Задачи на завтра** - задачи с дедлайном завтра
- **Остальные задачи** - задачи с дедлайном в течение недели

**Отображение задач:**
- Название задачи
- Создатель задачи
- Срок выполнения
- Приоритет (визуально для срочных)
- Индикация просрочки (дни и часы)
- Цветовая индикация статуса (обводка карточки)

### 2.8. Статистика и аналитика

#### 2.8.1. Общая статистика
- Количество мероприятий (активных, завершенных, планируемых)
- Количество задач по статусам

- **Фреймворк:** React 18+

- **Календарь:** FullCalendar
- **Drag-and-Drop:** dnd-kit

#### 3.1.3. Интеграции
- **Google Drive API** - для работы со ссылками на Google Диск
- **Firebase Cloud Messaging (FCM)** - для push-уведомлений

### 3.2. Структура базы данных

#### 3.2.1. Основные модели
- **User** (Django User) - пользователи системы
- **Employee** - расширенная информация о сотрудниках
- **Department** - отделы организации
- **Category** - категории мероприятий
- **EventCard** - мероприятия
- **CardApproverOrder** - порядок согласующих плана мероприятия
- **Task** - задачи
- **TaskHistory** - история изменений задач
- **TaskAttachment** - вложения к задачам
- **TaskComment** - комментарии к задачам
- **Notification** - уведомления
- **FCMDevice** - устройства для push-уведомлений

#### 3.2.2. Связи между моделями
- Employee → User (OneToOne)
- Employee → Department (ForeignKey)
- Employee → Employee (delegate_to, ForeignKey для замещения)
- EventCard → Employee (created_by, ForeignKey)
- EventCard → Department (responsible_department, ForeignKey)
- EventCard → Department (shared_departments, ManyToMany)
- EventCard → Category (categories, ManyToMany)
- EventCard → Employee (approvers, ManyToMany через CardApproverOrder)
- Task → EventCard (card, ForeignKey, опционально)
- Task → Employee (created_by, assigned_employee, redirected_by, ForeignKey)
- Task → Department (assigned_department, ForeignKey)
- Task → Employee (recipients, cc, ManyToMany)
- Task → Task (parent_task, ForeignKey для связанных задач)
- TaskHistory → Task (task, ForeignKey)
- TaskHistory → Employee (employee, ForeignKey)
- TaskAttachment → Task (task, ForeignKey)
- TaskComment → Task (task, ForeignKey)
- TaskComment → Employee (author, ForeignKey)
- Notification → User (user, ForeignKey)
- FCMDevice → User (user, ForeignKey)
